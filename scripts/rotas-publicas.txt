# Rotas PÚBLICAS por desenho — cada uma com a razão. Tudo o que não estiver
# aqui tem de ter extractor de autenticação (ver check-route-auth.sh).
#
# Acrescentar uma linha a este ficheiro é uma decisão de segurança. Se não
# souberes escrever a razão, a rota não devia ser pública.

/health                      Sonda de liveness. Devolve "ok" e mais nada.
/api/status                  Estado público (api/db/uptime/versão) — sem dados de inquilino.
/metrics                     Contadores Prometheus. NÃO é exposto no ingress k8s (deploy/k8s/02-server.yaml) nem pelo nginx (que só encaminha /api, /ws, /rtc): o scrape vai directo ao pod. Se algum dia for exposto, passa a precisar de autenticação.
/api/auth/register                    Registo público — cria organização + administrador.
/api/auth/login                       Autenticação. É o que produz o token.
/api/auth/refresh                     Rotação do refresh token; autentica-se pelo cookie HttpOnly, não por header.
/api/auth/logout                      Revoga a sessão; sem token não há nada a revogar.
/api/auth/sso/discovery                   Descobre se um domínio tem SSO. Anterior a qualquer sessão.
/api/auth/sso/authorize                   Início do fluxo OIDC. Anterior a qualquer sessão.
/api/auth/sso/callback                Retorno do IdP. A prova é o código de autorização + PKCE, não um token nosso.
/api/public/settings         Dois booleanos de aparência (esconder criação de org / botão SSO). Sem dados de inquilino.
/api/public/recordings/{token}           Partilha de gravação por link. A credencial É o token no caminho, validado no handler.
/ws                          WebSocket de sinalização. Autentica pelo ROOM TOKEN no query string (JWT separado, âmbito de uma sala, expira em minutos) — um extractor de header não serve num WebSocket.
/rtc                         WebSocket de presença. Autentica pelo access token no query string, pela mesma razão.
/api/rooms/{room_code}/live  Emissão em directo (ADR-0003). Autentica pelo ROOM TOKEN no query string e CONFERE que o id da sala do token bate com o código do caminho — um extractor de header não serve num WebSocket, pela mesma razão do /ws. A chave RTMP viaja na query e NUNCA é registada: o `Secret` redige-a no Debug e o handler nunca imprime a query.
/api/operator/v1/organizations                  Provisionamento de organizações. Autentica por PROVISIONING_SECRET em header; vazio => desactivado (fail-closed).
/api/public/recordings/{token}/content  Descarrega a gravação partilhada. A credencial É o token no caminho, validado no handler — igual a /api/public/recordings/{token}.
/api/public/whiteboards/{token}/image  PNG de um quadro partilhado por link. A credencial É o token no caminho.
/api/auth/login/mfa                Segunda metade do login. A credencial É o token de desafio no corpo (JWT `typ: "mfa"`, 5 min, que não abre mais nenhum endpoint) mais o código do segundo factor.
/ready                       Sonda de readiness. Devolve "ready" ou "draining" e mais nada — nem dados de inquilino, nem contagens. O K8s tem de a poder ler sem credenciais, tal como a de liveness.
/api/openapi.json            Contrato OpenAPI da BFF (ADR-0006 §3). Descreve rotas, não dados; é o mesmo ficheiro commitado em docs/reference/openapi/.
/api/v1/openapi.json         Contrato OpenAPI da v1 pública. Igual ao commitado em docs/reference/openapi/.
/api/operator/v1/openapi.json          Contrato OpenAPI da superfície de operador. Descreve rotas, não dados.
/api/integrations/openapi.json         Contrato OpenAPI das integrações (Odoo, agente SMS). Descreve rotas, não dados.
/api/studio-pairings         Troca do código de emparelhamento por um token de fonte (ADR-0014 §2.1). A credencial É o código de uso único no corpo (localizador + segredo, 10 min, 5 tentativas, só o hash guardado): o telefone da app Delonix Câmara entra SEM conta, por isso não há token anterior que um extractor pudesse exigir. Rate-limit por IP no handler, e a recusa é sempre o mesmo `studio.pairing_invalid` para não revelar qual das metades falhou.
/api/rooms/{room_code}/guest-join  Entrada de convidado SEM conta (alavanca 1 da adopção). É pública por ser o ponto: quem entra não tem conta. Só emite um ROOM TOKEN (`typ: "room"`, `origin: "guest"`, `guest: true`, minutos) que nenhum extractor da API aceita e que o /ws força a passar pela SALA DE ESPERA; a sala pode recusar (`allow_guests = false` → 403). Travão por IP e por sala com 429 + Retry-After; auditado como `room.guest_join`. Ver server/src/guests.rs.
/api/auth/login/mfa/passkey-options   Opções WebAuthn do segundo factor. A credencial É o token de desafio no corpo (JWT `typ: "mfa"`, 5 min), como em /api/auth/login/mfa; só devolve desafios para as chaves dessa conta.
/api/auth/login/mfa/passkey           Segunda metade do login com chave de acesso. A credencial É o token de desafio mais a asserção WebAuthn verificada contra a cerimónia (uso único, 5 min).
/api/users/me/data-exports/{export_id}/content  ZIP de «os meus dados» por link temporário. A credencial É a assinatura HMAC (exp ≤ 15 min) validada no handler, como os PNG assinados dos quadros; assinatura errada ou vencida dá 404.
/api/public/extension-provisioning/{token}  Configuração do Linphone por QR (R278). O telefone que lê o QR não tem conta: a credencial É o token no caminho (256 bits, só o SHA-256 guardado, uso único, 10 min), gasto de forma atómica. Responde 404 `ramais.provisioning_invalid` igual para inexistente/usado/expirado/ramal inactivo; rate-limit por IP com 429 + Retry-After; o caminho sai redigido no span HTTP e o token não entra na auditoria. É um GET com efeito (troca a password SIP) porque é assim que o Linphone descarrega a configuração.
